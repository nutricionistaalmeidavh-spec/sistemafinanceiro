# E10–E13 Operations Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver alerts, receipts/reports, validated backup/restore, and optional LAN access without adding any paid or cloud dependency.

**Architecture:** Add four focused services (`alerts`, `reports`, `backup`, `lan`) behind the existing Electron IPC/RBAC boundary. Persist only state that cannot be derived from existing financial data. Reuse SQLite, built-in Node APIs, and the already-vendored ArtiSys modules/contracts.

**Tech Stack:** Node 22, Electron, React, TypeScript, SQLite/better-sqlite3, native `node:http`, native `node:crypto`, ArtiSys PDF/printing contracts.

**Spec:** `docs/superpowers/specs/2026-09-12-e10-e13-ops-design.md`

## Global Constraints

- Core runtime remains R$ 0 / self-hosted / local-first.
- No paid service or external cloud dependency.
- No automatic GitHub Actions consumption.
- LAN disabled by default.
- Restore validates before replacing the active database and creates a safety backup first.
- Reports/exports work without Microsoft Office.
